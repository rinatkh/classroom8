## Что заметить, спросить и запустить

1. **List.** Сначала покажите исходные три узла, затем один InsertAfter. Узлы не обязаны лежать в логическом порядке. Пауза: «Что потеряем, если сначала заменить at.Next?» После — `make run-01_linkedlist` и тест `TestListContracts`.
2. **Reverse.** Остановитесь после одного переназначения: старая связь уже стёрта, следующий узел надо было сохранить. Вопрос: «Почему previous недостаточно, чтобы продолжить обход?» После — `go test ./internal/linkedlist -run TestReverseTrace -v`. Next виден как ещё не развёрнутая связь current; отдельный указатель next обсуждаем по Go-коду.
3. **Stack Array.** Введите 7 → Push, дождитесь конца; затем 9 → Push → Pop. При проверке наблюдались перенос 7 в первый слот и top=1. Вопрос: «Какой край обслуживает и вставку, и удаление?» После — `make run-02_stack`.
4. **Stack List.** Введите 9 → Push; дождитесь появления ссылки top на новый узел. Вопрос: «Зачем узлу Next, если операция только с вершиной?» После — тот же пример, сравнить Slice.Pop и Linked.Pop. Для первого просмотра одного узла достаточно; второй Push показывает связь с прежним top.
5. **Queue Array.** Введите 12 → Enqueue, затем 20 → Enqueue, затем Dequeue. При проверке перенос 12 изменял tail с 0 на 1. Вопрос: «Почему это другой порядок, чем Pop стека?» После — `make run-03_queue`, затем `make run-05_ringbuffer`. Модель USF с индексами не подменяет наш slice-shift baseline и не обещает тот же контракт full/empty.
6. **Queue List.** Введите 3 → Enqueue: обе стрелки указывают на первый узел. Вопрос: «Что сделать с tail после удаления последнего элемента?» После — `make run-03_queue` и тесты пустого перехода.
7. **Buffer.** Покажите Write(Go ), Write(API), Read(3), затем Reset. Пауза: «Почему len=0, а capacity не ноль?» После — `make run-04_buffer`; снимки можно получить командой `go run ./cmd/07_visualizations -buffer`. Рисуется логический непрочитанный хвост, а не физические адреса; capacity получена от Go 1.22.
8. **Ring GIF.** Проследите один переход стрелки через последний слот. Вопрос: «Как отличить empty от full при совпавших индексах?» После — `make run-05_ringbuffer`. В GIF используется зазор между чтением и записью; наш Ring хранит size и использует все cap слотов, reject-on-full. Схема автора не является спецификацией Go-контейнера. Автор Muhannad Ajjan, CC BY-SA 4.0; файл не включён в patch.
9. **Chaining.** Режим Hash Integer; Insert 14, дождаться конца, Insert 27. При проверке оба узла оказались в bucket 1. Вопрос: «Равный hash означает равные ключи?» После — `make run-06_hashtable` и `go test ./internal/hashtable -run TestTableOperations -v`. USF показывает integer modulo, наша таблица — string/FNV; это общая стратегия, не внутренности Go map.
10. **Probing.** Оставьте Linear Probing: Insert 1, дождаться конца, Insert 30. При проверке 30 занял слот 2 после занятого слота 1. Вопрос: «Почему при удалении нельзя просто оборвать цепочку поиска пустым слотом?» После — разбор контраста в `docs/structures.md`; production-стратегия classroom остаётся chaining, вторую таблицу не пишем.
11. **MP4.** Пауза на 12 с: owl/elk в цепочке; на 23 с: chaining рядом с probing. Вопрос: «Почему одинаковый счётчик checks ещё не означает одинаковые ns/op?» После — `make run-06_hashtable`.
12. **Rehash.** До четвёртого ключа n=3, m=4; после m=8. Вопрос: «Почему недостаточно скопировать только головы старых buckets?» После — `go test ./internal/hashtable -run TestResize -v`.

У USF есть Pause/Step/Skip и регулировка скорости. Дождитесь завершения операции перед следующей: во время движения кнопки ввода отключаются. Названия Open/Closed Hashing на сайте — терминология автора; в уроке используем однозначные названия separate chaining / open addressing.

## Кандидаты, которые не выдаём за просмотренные ролики

- [AlgoVizuals: Reverse Linked List](https://www.youtube.com/watch?v=2ZstIFnc6ns): поисковая карточка описывает prev/current/next; проигрывание и фактическая длительность недоступны для проверки. Это кандидат, не подтверждённый пункт основной подборки.
- [Depth First: Linked List Animation](https://www.youtube.com/watch?v=922Dxbxyapg): проверены только публичные метаданные; движение и длительность не подтверждены.
- [VisuAlgo List](https://visualgo.net/en/list): официальный интерактивный материал NUS для списка, stack/queue и дополнительных операций; содержание страницы найдено, интерактивный сценарий в этой проверке не проигрывался. Подходит для самостоятельного знакомства после основной подборки, если доступен в вашем браузере.

Предложенный пример [Instagram DeqT_bITz0M](https://www.instagram.com/reel/DeqT_bITz0M/) по публичному описанию посвящён **Redis caching**, а не структурам этого занятия. Использован как ориентир короткого формата; в подтверждённую тематическую подборку не включён. Для других Reels не удалось подтвердить подходящий ролик и движение без ограничений доступа; ссылки и длительности не выдуманы. Урок и домашняя работа полностью доступны без Instagram.
