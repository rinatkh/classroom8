# Схемы, видео и движение данных

Откройте [visualizations.html](visualizations.html) локально в браузере. Никаких CDN/сети/сервера. Сцены list/reverse/stack/queue/ring/hash, кнопки назад/вперёд, ползунок и autoplay. Данные встроены из [trace-data.json](trace-data.json), который выдаёт `go run ./cmd/07_visualizations`. Смена шага показывает конкретное изменение связей или индексов. Красный/жёлтый full — отказ, прежние данные не исчезают.

## Реальный ролик из исходного архива

В переданном архиве доступен [assets/collisions.mp4](assets/collisions.mp4): 29,781 с, H.264, 720×1280, AAC. Файл сохранён побайтно. Исторический путь из другой папки курса в этом архиве не подтверждён и не используется как ссылка.

На **слайде 42**:

1. До запуска: hash выбирает bucket; разные ключи могут попасть в один. Это модель таблицы, не конкретная версия Go map.
2. Пауза **12.0 s**: видна цепочка owl/elk. Спросить, какую связь пройти при поиске второго ключа.
3. Пауза **23.0 s**: рядом chaining и probing. Спросить, почему поиск probing должен повторять путь вставки и почему удаление требует tombstone/другого корректного правила.
4. После видео: `make run-06_hashtable`, затем `go test ./internal/hashtable -run 'TestTableOperations|TestResize' -v`.

Счётчик checks в анимации не является временем Go benchmark. Число одинаковых checks не обещает одинаковые ns/op или allocation. Основная реализация classroom — chaining; probing остаётся концептуальным сравнением. Ролик не показывает весь контракт нашей реализации.
